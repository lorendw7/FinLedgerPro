[English](README.md) | [简体中文](README.zh-CN.md)

## 项目定位

FinLedger Pro 是一款本地桌面财务应用，包含两个完全免费的功能模式：

- **Basic——个人记账：** 管理现金、银行卡、电子钱包、信用卡、收入、支出、转账、预算和消费分析，不要求用户先懂借贷记账。
- **Pro——企业会计：** 面向初创公司和小微企业，提供科目表、复式记账、应收应付、数据标注计件结算、银行对账、项目利润、三大报表、多主体与多币种。

所有核心账务数据都保存在用户自己的电脑中。软件不依赖强制云服务、不要求注册托管账号，也没有订阅、广告、许可证密钥或功能付费墙。公司可以建立独立私有仓库，依赖公开核心的正式版本，保存自己的品牌、科目映射、发票模板、经营流程和供应商配置。

“Pro”表示专业级会计能力，不表示付费版本。Basic 与 Pro 全部使用 MIT 许可证公开源代码。

## 公开核心与公司私有定制

维护者目前没有商业化 FinLedger Pro 的计划：

- 不提供由维护者扣留功能的付费私有版；
- 不收订阅费；
- 不加入广告；
- 不设置许可证密钥；
- 不把高级功能留在闭源版本；
- 不默认收集遥测或财务数据。

公开仓库发布完整可用的会计核心和参考应用。下游公司可以把公司特有扩展保留在自己的私有仓库中，这不等于 FinLedger Pro 维护者经营“开源基础版 + 闭源收费版”。推荐关系是**公司私有仓库 → 公开核心正式版本**，而不是长期维护私有 fork。

MIT 是宽松开源许可证，允许其他人商业使用、修改和分发代码，只要遵守原始版权及许可证声明要求。“项目不商业化”是维护者的产品承诺，不会取消 MIT 已授予第三方的权利。详细边界见[公开核心与公司私有仓库](docs/public-core-and-private-company-repos.zh-CN.md)。

## 借鉴 Xero，但不是复制 Xero

[Xero](https://www.xero.com/us/accounting-software/) 是成熟的中小企业云会计软件。FinLedger Pro 借鉴它公开展示的工作流和内部控制思路：

```text
联系人 → 发票 / 账单 → 收付款记录 → 银行对账 → 财务报表
```

重点借鉴：

- 把银行对账设计成经常执行的核心工作区；
- 以账单、发票、结算单等源单据驱动会计分录；
- 在联系人页面集中展示应收、应付和付款历史；
- 按项目追踪收入、成本和毛利；
- 使用期间锁定和审计轨迹保护历史账目；
- 自动化只提供建议，最终由用户确认。

FinLedger Pro 与 Xero 没有隶属、合作或授权关系，不使用 Xero 的源代码、商标、截图或专有资源。完整分析见 [Xero 功能借鉴](docs/xero-product-benchmark.zh-CN.md)。

## 系统核心设计

企业业务采用“窄腰架构”：

```text
业务单据与子账 → 唯一复式记账内核 → 报表与分析
                    借方 = 贷方
```

发票、账单、外部付款会计记录、标注员结算、资产折旧等模块只负责把业务事实转成平衡分录。试算平衡、三大报表和分析统一读取总账。新增业务功能时增加子模块和过账规则，不重写会计内核。

详细设计和架构图见 [系统架构](docs/architecture.zh-CN.md)。

### 技术架构

| 层级 | 技术 | 作用 |
|---|---|---|
| 桌面外壳 | Electron | Windows、macOS、Linux 桌面应用 |
| 前端 | React + Tailwind CSS | Basic/Pro 界面和中英文切换 |
| 本地后端 | Python FastAPI | 领域逻辑和本地 HTTP 服务 |
| 数据库 | SQLite | 本地账簿、事务和迁移 |
| AI | Ollama + LangGraph | 可选本地分析，不控制账簿 |
| 税务知识库 | ChromaDB + RAG | 带来源的参考查询，不负责申报 |
| 开放集成层 | 可替换供应商适配器 | 汇率和只读银行流水；必须支持离线降级，不提供付款接口 |

## 多币种与开放 API

数据库从第一天起采用 ISO 4217 货币代码。首批生产验收覆盖 SGD 与 CNY，之后可增加 USD、EUR 等货币而不修改核心表结构。

每套企业账簿有一个**本位币**；每笔交易同时保留：

- 原币和原币金额；
- 本位币和本位币金额；
- 使用的汇率；
- 汇率日期、来源和获取时间；
- 是否由用户手工覆盖；
- 舍入规则版本。

首批汇率候选来源：

- [Frankfurter](https://frankfurter.dev/)：开源、无需密钥、可以自行部署；
- [ECB Data API](https://data.ecb.europa.eu/help/getting-data-web-services-sdmx-0)：官方参考数据，包含 SGD/CNY；
- 手工汇率：银行、合同、法定或会计师确认的汇率，始终可用。

外部汇率只作为建议。已过账交易永久保留当时的汇率快照；供应商故障时依次使用备用来源、本地缓存和手工录入，不能影响正常记账。

银行集成只读取账户、余额和流水，所有数据必须先暂存、查重并人工确认对账。系统不创建或批准转账，不管理收款人，不发起付款、退款、在线收款或银行卡操作。账簿中的“已付款/已收款”是外部资金移动形成的会计事实。

完整设计见 [开放 API 与多币种策略](docs/open-api-and-multi-currency.zh-CN.md)。

## 数据标注业务的首个生产闭环

```text
标注成果验收
→ 按合格数量和单价计算结算
→ 确认项目成本与应付款
→ 导入银行付款流水
→ 银行对账
→ 试算平衡与财务报表
→ 月结、备份并锁定期间
```

核心数据要求：

- `employment_type` 表示用工关系；
- `pay_method` 表示月薪、时薪或计件，两者不能混为一个字段；
- 计件按 `accepted_qty × unit_price` 计算；
- 单价在产量记录中保存历史快照；
- 已进入结算单的产量不能重复结算；
- 用工性质和税务处理由实际事实及适用法律决定，软件配置不能替代专业判断。

## 不可违反的财务正确性规则

1. 所有金额使用 `Decimal`，不使用二进制 `float`。
2. 企业会计分录永远满足借方合计等于贷方合计。
3. 已过账记录不原地修改，通过冲销、贷项通知单或更正分录纠错。
4. 余额由交易历史计算，不维护容易漂移的可变余额字段。
5. 收入确认和实际收款是两个不同事件。
6. 个人账和企业账在结构上隔离，不能合并。
7. 每笔外币交易保留当时的汇率来源和快照。
8. 创建、过账、付款记录、结算和导入操作必须幂等，重试不能重复记账。
9. 银行流水先进入暂存区，完成查重和人工确认后再记账。
10. 关闭期间后禁止普通修改；解锁必须留下审计记录。
11. 备份必须通过自动恢复验证，只有“生成过”但从未恢复测试的文件不算可靠备份。

## 产品路线

项目不再承诺七周完成，而是按质量门槛推进：

| 里程碑 | 主要内容 |
|---|---|
| M0 | 定位、架构、Xero 借鉴、范围与可靠性标准——已完成 |
| M1 | 本地基础、`Decimal`、迁移、审计、幂等、备份和恢复 |
| M2 | 科目表、复式过账、试算平衡、期初余额和期间锁定 |
| M3 | 账单、数据标注计件结算、应付、银行文件导入、只读流水接口与对账 |
| M4 | 合同、发票、应收、收款、账龄和项目利润 |
| M5 | 月结流程、三大报表、追溯、固定资产和导出 |
| M6 | 多币种、多主体、汇兑损益、往来和合并报表 |
| M7 | 完整个人记账、预算、信用卡、净资产和消费分析 |
| M8 | 加密、完整测试、诊断、签名安装包和影子账验证 |
| M9 | 可选 AI、预测、税务 RAG 与只读外部集成 |

使用真实账目之前，必须至少完成一整个月的**并行影子账**：现有记账方式和 FinLedger Pro 同时记录，并逐项核对银行、应收、应付、税务控制科目和试算平衡。详细门槛见 [产品与学习路线图](docs/product-roadmap.zh-CN.md)。
