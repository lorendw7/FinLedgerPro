# 公开核心与公司私有仓库

[English](public-core-and-private-company-repos.md) | [简体中文](public-core-and-private-company-repos.zh-CN.md)

> **状态：** 已接受的架构决策
>
> **决策：** FinLedger Pro 在公开仓库发布可复用的会计核心和参考应用；每家公司可以建立独立私有仓库，并依赖公开核心的正式版本。

---

## 1. 仓库边界

公开项目是完整可用的会计基础，不是托管服务，也不是为私有收费版引流的残缺核心。适合所有使用者共享和共同验证的通用能力放在公开仓库：

- 账套、账户、`Decimal` 金额、审计事件、迁移、备份和恢复；
- 科目表、借贷平衡过账、日记账、试算平衡、期间锁定和财务报表；
- 联系人、账单、发票、贷项通知单、应收应付、收款和付款会计记录；
- 银行流水暂存、查重、匹配、对账及只读银行流水接口；
- 稳定的扩展契约、参考适配器和契约测试。

公司自己的私有仓库只保存该公司特有的内容：

- 品牌、导航和公司专属页面；
- 科目映射、发票模板、审批制度和经营配置；
- 私有流程及集成，例如 Aspire 只读流水适配器；
- 部署配置和内部操作文档。

依赖方向永远只有一个：

```text
公司私有仓库
    │
    │ 依赖公开核心的已发布版本
    ▼
FinLedger Pro 公开核心
```

公开核心不能导入、调用或要求任何公司私有代码。推荐通过版本化依赖使用公开核心，不长期维护私有 fork。只有暂时无法通过扩展契约表达的核心修复，才短期保留私有补丁。

---

## 2. 扩展契约

私有模块只能通过公开契约使用核心：

- 源单据通过会计内核的命令创建草稿和过账；
- 报表读取公开的账本视图或查询服务；
- 扩展拥有自己的私有表和迁移，不直接修改核心表；
- 银行适配器把标准化流水送入公开核心的暂存区；
- 扩展不得直接写入日记账行、余额或对账决定。

每个公开版本提供契约测试，公司私有仓库必须在 CI 中运行。扩展接口、数据库迁移和标准数据模型都遵守语义化版本规则。

---

## 3. 只读银行能力范围

FinLedger Pro 可以读取银行数据，但不控制资金移动。公开银行契约有意限定为只读：

```text
BankFeedProvider
  list_accounts()
  get_account_balance(account_id)
  list_transactions(account_id, cursor, date_range)
  health_check()
```

供应商数据只能沿以下路径进入账簿：

```text
银行 API 或流水文件
  → 不可变导入批次
  → 标准化银行流水
  → 指纹和重复检查
  → 匹配建议
  → 人工确认对账
  → 会计记录和审计证据
```

适配器必须保留供应商交易 ID、状态、记账/价值时间、原始金额和币种、收支方向、摘要、分页游标、获取时间及安全的载荷哈希。待入账与已结算流水不能混淆；重复导入同一页或同一笔交易只能产生一次效果。

### 明确不在范围内

FinLedger Pro 不会：

- 创建或批准银行转账；
- 管理收款人；
- 发起批量付款、自动扣款、退款或在线收款；
- 签发或控制银行卡；
- 向界面暴露付款凭证；
- 未经暂存和对账就把银行接口响应直接作为正式分录。

账本可以记录发票已经收款、应付款已经结清。这是从银行流水观察到或附证据录入的会计事实，不是向银行发送的付款指令。

---

## 4. 秘密信息与财务数据

私有 Git 仓库也不是秘密管理工具。API 密钥、访问令牌、真实银行响应、账簿数据库、导出和备份不得提交到公开或私有仓库。运行时凭证应保存在操作系统密钥链或获批的秘密管理服务中，并使用银行提供的最小只读权限。

与供应商无关的通用代码通常应贡献回公开核心。公司科目映射、私有流程和部署细节留在公司仓库；如果供应商条款允许，且不包含公司数据或凭证，通用供应商适配器也可以公开。

---

## 5. 许可证

公开仓库继续使用 MIT 许可证。公司可以把自己的专属仓库保持私有，也可以在遵守 MIT 声明要求的前提下，把公开核心用于内部或商业软件。这不是 FinLedger Pro 自己保留的闭源收费版：维护者不扣留付费功能层，而下游公司拥有并控制自己的扩展。
