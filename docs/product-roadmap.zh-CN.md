# FinLedger Pro——产品与学习路线图

[English](product-roadmap.md) | [简体中文](product-roadmap.zh-CN.md)

> **状态：** 当前有效计划
>
> **计划方式：** 按质量门槛完成里程碑，不承诺固定周数
>
> **协作方式：** 作者亲自编写全部应用代码；教学和讨论采用中英文；代码注释使用英文。

---

## 1. 计划原则

1. **先完成真实财务闭环，再扩充功能。** 首个企业版本必须支持一条可以对账、结账和出报表的实际业务流程。
2. **先保证可信，再增加自动化。** 审计、冲销、备份恢复和银行对账必须早于 AI 自动化和便利型集成。
3. **使用质量门槛，不使用日期代替完成度。** 只有验收与恢复测试全部通过，里程碑才算完成。
4. **源单据驱动会计。** 账单、发票、结算单和有外部证据的付款记录通过过账规则生成分录。
5. **人工确认具有最终权威。** 规则和 AI 可以建议，但用户确认后才能产生财务影响。
6. **边开发边学习会计。** 每个阶段先学习财务概念，再实现，并用虚构案例核对结果。
7. **多币种从模型开始，接口从离线开始。** M1 即保存货币和汇率元数据，M6 才完成完整汇兑与合并功能；外部 API 始终可替换和降级。

原有“七周完成”的安排已经废止。它可以说明学习顺序，但不能作为单人开发生产级会计软件的安全承诺。

## 2. 里程碑

### M0——产品定义和对标研究（已完成）

**学习内容：** 记账循环、产品范围以及银行对账为什么重要。

**交付：**

- 产品定位、Basic/Pro 边界和本地优先原则；
- 窄腰架构、Xero 功能借鉴；
- 开放 API 与多币种策略；
- 公开核心/公司私有仓库边界和只读银行能力范围；
- 财务正确性规则和生产发布门槛；
- MIT 许可证、贡献规则和中英文文档规范。

**退出门槛：** 所有文档对范围、术语、建设顺序和非目标的表述一致。

### M1——可信的本地基础

**学习内容：** 会计主体假设、金额精度、源单据、审计证据和本位币。

**交付：**

- Electron、React、FastAPI 和 SQLite 的端到端最小路径；
- 相互隔离的 `PERSONAL` 和 `BUSINESS` 账簿；
- `Decimal`、ISO 4217 货币、本位币、日期、时区和稳定标识；
- 数据库迁移、审计事件和不记录财务敏感值的结构化日志；
- 自动轮换备份、恢复流程和启动完整性检查；
- 创建、过账和导入命令的幂等基础；
- 一条个人交易和一张企业源单据完整贯通。

**退出门槛：** 强制崩溃不会留下半笔交易；备份能恢复到干净安装；同一请求重试两次只产生一次财务影响；断网时核心流程仍能使用。

### M2——企业会计内核和期初建账

**学习内容：** 五大会计要素、借贷规则、权责发生制、试算平衡和期初余额。

**交付：**

- 科目表、科目类型和报表映射；
- 日记账、分录行、借贷平衡检查和事务过账；
- `DRAFT → APPROVED → POSTED → REVERSED` 状态流程；
- 试算平衡和总账下钻；
- 启用日期和受控期初余额导入；
- 会计期间和锁定日期。

**退出门槛：** 属性测试证明所有已过账分录平衡；已过账历史不能原地修改；试算平衡可以从日记账重建；关闭期间拒绝普通修改。

### M3——支出、标注结算和银行对账

**学习内容：** 费用与资产、应付账款、成本确认、代扣、项目成本和银行对账。

**交付：**

- 同时支持客户、供应商和承包者角色的联系人；
- 账单、直接费用、附件、到期日、应付账龄和付款状态；
- 标注项目、产量、质量验收、版本化计件单价、承包者结算和项目成本；
- CSV / OFX / QIF 银行流水暂存导入，以及供公司扩展使用的只读 `BankFeedProvider` 契约；
- 文件与流水指纹、查重、匹配、拆分、转账和对账报告；
- 行动中心：待对账、到期账单、待结算和备份健康状态。

**退出门槛：** “合格产量 → 结算 → 应付 → 外部执行付款 → 导入流水 → 银行对账 → 成本报告”无需电子表格即可完成；重复导入和重复结算测试通过；任何银行接口都不能发起资金移动。

### M4——收入、收款和对账

**学习内容：** 收入确认、应收账款、贷项通知单、定金、部分收款和坏账。

**交付：**

- 客户合同/项目、报价（确有需要时）、发票、贷项通知单和收款；
- 付款条件、部分收款、提醒和应收账龄；
- 现金收款与收入确认分离；
- 客户收款的银行匹配；
- 项目收入、成本、必要时的在制品和毛利。

**退出门槛：** “客户项目 → 发票 → 应收 → 收款 → 对账 → 项目毛利”完整运行，并安全处理取消、部分付款和多付款。

### M5——月结与财务报表

**学习内容：** 调整分录、应计、待摊、折旧、月结和三大报表之间的关系。

**交付：**

- 月结清单：完成银行对账、检查应收应付、计提、异常复核、报表、备份和期间锁定；
- 利润表、资产负债表、现金流量表、应收/应付账龄和银行对账报告；
- 报表数字下钻到分录、源单据和附件；
- 同比期间、预算差异、项目/成本中心筛选、Excel/PDF 导出；
- 固定资产台账和直线折旧。

**退出门槛：** 会计师能够把每个余额追溯到证据；资产负债表和现金对账不变量通过；恢复后可以复现已关闭月份。

### M6——多币种与多主体

**学习内容：** 本位币与交易币、已实现/未实现汇兑损益、公司间往来和合并。

**交付：**

- SGD、CNY 首批完整支持，并验证 USD、EUR 扩展；
- 可替换的 Frankfurter / ECB / 手工汇率适配器、本地缓存和离线降级；
- 每笔交易保存汇率快照、来源、日期和舍入规则；
- 已实现与未实现汇兑损益；
- 新加坡和中国法律主体账簿隔离；
- 公司间科目、抵销分录和合并报表。

**退出门槛：** 刷新汇率不能改变历史；供应商切换不能重写账簿；主体数据不串账；抵销后合并报表平衡；断网状态仍可结账。

### M7——完整个人财务模式

**学习内容：** 现金预算、净资产、信用卡负债、转账和储蓄率。

**交付：**

- 个人收入、支出和转账快速录入；
- 账户、层级分类、预算、预警、需要/想要标签、周期费用识别和 CSV 导出；
- 信用卡消费计入支出和负债，信用卡还款只作为账户转账；
- 个人净资产和消费报告，严格隔离企业账簿。

**退出门槛：** 转账不影响消费额；余额完全由交易历史计算；个人账不能与企业账合并。

### M8——生产加固和候选发布版

**学习内容：** 威胁建模、恢复目标、供应链风险、发布管理和运维支持。

**交付：**

- 数据库静态加密、系统密钥链、自动锁定和密码恢复说明；
- 依赖锁定和漏洞扫描；
- 单元、属性、集成、端到端、迁移、导入、崩溃和恢复测试；
- 不包含财务数据的诊断导出；
- 签名安装包、可复现构建、语义化版本、升级和回滚手册；
- 所有支持版本之间的迁移测试矩阵。

**退出门槛：** 所有支持系统的生产检查通过，并至少完成一个完整月度的并行影子账核对。

### M9——可选智能与集成

**学习内容：** 可解释自动化、预测限制、检索质量和人工审批。

**仅在 M8 后交付：**

- 规则建议、异常检测和现金流预测；
- 本地 Ollama / LangGraph 分析，展示证据和可信度；
- 带司法辖区、发布日期和来源引用的税务 RAG，不负责申报；
- 确有需求时再增加只读外部集成；银行供应商只能读取账户、余额和流水。

**退出门槛：** 关闭 AI 或供应商不改变任何会计结果；AI 不能独立过账、删除、对账或锁定账目；集成层不暴露付款、批量付款、收款人、银行卡、退款或在线收款命令。

## 3. 版本建议

| 版本 | 含义 |
|---|---|
| `0.1.0` | M1 学习版，不能作为唯一账簿 |
| `0.2.0` | M2 会计内核 |
| `0.3.0` | M3 首条完整企业闭环 |
| `0.4.0` | M4 收入闭环 |
| `0.5.0` | M5 月结和报表，可开始影子账 |
| `0.6.0` | M6 多币种和多主体 |
| `0.7.0` | M7 完整 Basic 模式 |
| `0.9.0-rc` | M8 候选发布版 |
| `1.0.0` | 生产门槛和并行影子账全部通过 |

版本表示能力和可信程度，不表示开发用时。

## 4. 真实账目安全启用方式

1. M4 前只使用虚构数据。
2. M5 使用明确启用日期和核对过的期初余额创建干净账簿。
3. 至少一个完整月份同时维护现有账目和 FinLedger Pro 影子账。
4. 逐项核对银行、应收、应付、税务控制科目和试算平衡。
5. 请会计师或合格记账人员复核科目表、期初余额、过账规则和首个月结。
6. 只有通过 M8 后才考虑将其升级为主要账簿。
7. 始终保留可以导出、可以恢复的备份和回退方案。

## 5. v1 之后

未来可能增加采购订单、库存、正式员工工资、费用报销、预算预测、多人审批、会计师访问和更多只读银行流水适配器。只有出现真实经营需求时才实施，并继续遵守源单据、过账、对账和审计契约。

发起付款、执行批量付款、管理收款人、自动扣款、在线收款、退款以及银行卡签发/控制明确不进入产品路线。FinLedger Pro 只记录外部资金移动形成的会计结果，并与读取到的银行事实对账。

“支持小公司”指可靠覆盖核心财务经营循环，不表示 v1 就取代 HR、CRM、法务、税务申报、银行或完整 ERP。
