# Xero 产品借鉴——FinLedger Pro 应该学习什么

[English](xero-product-benchmark.md) | [简体中文](xero-product-benchmark.zh-CN.md)

> **状态：** 产品研究与设计指导
>
> **目的：** 学习成熟小企业会计软件的工作流和控制方法，不复制其云端模式、界面、品牌或实现。

---

## 1. Xero 是什么

Xero 是面向中小企业的云端会计平台。它的主要价值不是某个孤立功能，而是把日常业务连接成完整循环：

```text
联系人 → 发票 / 账单 → 收付款记录 → 银行对账 → 报表
```

公开产品资料覆盖发票、账单、费用、银行对账、项目、工资、现金流和财务报表。FinLedger Pro 最值得学习的是**工作流完整性**：从取得源单据到财务报表之间，不应该再依赖额外电子表格进行补账。

官方资料：

- [Xero 会计软件概览](https://www.xero.com/us/accounting-software/)
- [Xero Accounting API 概览](https://developer.xero.com/documentation/api/accounting/overview)

## 2. 值得借鉴的功能思想

### 2.1 银行对账是日常核心工作区

Xero 把银行流水和账簿候选记录放在一起，支持匹配、分类、规则建议、未对账提示和对账报告。FinLedger Pro 通过本地 CSV / OFX / QIF 文件以及供公司扩展使用的只读银行流水契约取得银行事实：

1. 流水先进入暂存区；
2. 入账前检测重复文件和重复流水；
3. 建议匹配发票、账单、转账或已有交易；
4. 不确定的匹配必须人工确认；
5. 永久保存原始流水和对账决定；
6. 同时展示银行余额、账面余额和未解决差额。

参考：[Xero 银行对账](https://www.xero.com/us/accounting-software/reconcile-bank-transactions/)。

### 2.2 使用源单据，而不是让用户手写分录

企业主处理的是发票、账单、收据、结算单和付款，而不是日记账行。单据应采用清晰状态：

```text
DRAFT → APPROVED → POSTED → PAID / SETTLED
                          ↘ VOIDED by reversal
```

过账后生成不可原地修改的分录。错误通过冲销、贷项通知单或更正记录处理。手工分录只用于专业调整，不作为主要操作入口。

### 2.3 联系人页面应该回答财务问题

Xero 把每个联系人的发票、账单、贷项、付款和未清余额放在一起。FinLedger Pro 使用统一 `party/contact` 记录表示客户、供应商或承包者，并回答：

- 对方欠公司多少钱？
- 公司欠对方多少钱？
- 历史付款是否及时？
- 关联了哪些项目、单据和附件？
- 哪些项目已逾期或存在争议？

参考：[Xero 联系人管理](https://www.xero.com/us/accounting-software/organise-contacts/)。

### 2.4 用项目维度分析利润，不让科目表无限膨胀

Xero Projects 把工时、成本、费用、发票、预算和毛利关联到项目，并使用跟踪维度分析部门或地点。FinLedger Pro 将 `project`、`cost_center` 和标签作为单据行和分录行的分析维度。数据标注项目由此可以直接看到合格数量、承包者成本、客户收入和项目毛利，而不用为每个项目建立一套新科目。

参考：

- [Xero 项目核算](https://www.xero.com/us/accounting-software/track-projects/)
- [Xero Tracking Categories](https://central.xero.com/0/article/Set-up-tracking-categories)

### 2.5 把内部控制放进日常流程

- **期间锁定：** 防止关闭月份被误改；
- **历史与备注：** 记录谁在什么时间做了什么；
- **草稿和批准：** 不完整单据不进入账本；
- **对账状态：** 区分“已经记录的现金”和“已经被银行事实验证的现金”；
- **期初余额：** 使用明确的启用日期完成旧系统迁移。

参考：

- [Xero Lock Dates](https://central.xero.com/s/article/Set-up-and-work-with-lock-dates)
- [Xero History and Notes](https://central.xero.com/s/article/View-a-history-and-notes-summary-for-transactions-and-user-activity)
- [Xero Chart of Accounts](https://central.xero.com/s/article/View-your-chart-of-accounts)

### 2.6 自动化必须保留用户控制

有价值的自动化包括周期性发票/账单、银行规则、智能默认值、批量操作、重复检测和提醒。AI 建议需要展示证据，v1 不允许 AI 自主过账。

会计系统内部的创建、修改、付款记录、结算和导入接口都应使用幂等键，使网络重试或重复点击不会生成两张发票、两条付款记录或两笔分录。这不表示系统可以向银行发起付款。参考：[Xero 幂等请求](https://developer.xero.com/documentation/guides/idempotent-requests/idempotency/)。

## 3. 暂时不借鉴的能力

| Xero 能力 | FinLedger Pro 决定 | 原因 |
|---|---|---|
| 云端优先存储 | 不采用 | 本地所有权和离线使用是产品承诺 |
| 银行直连 | 只读扩展 | 只通过可替换供应商读取账户、余额和流水；全部流水先暂存并对账 |
| 发起付款或在线收款 | 不在范围内 | 资金移动增加支付、欺诈、争议、凭证和合规风险；系统只记录外部完成的结算 |
| 多人实时协作 | 延后，但保留审计字段 | 初期单人使用，未来仍可扩展 |
| 税务在线申报 | 不在范围内 | 需要认证、专业验证和持续法规维护 |
| 大型应用市场 | 暂不开发 | 第一版使用稳定导入导出已经足够 |
| AI 全自动过账 | v1 禁止 | 建议可能出错，真实账目必须人工确认 |
| 所有地区的完整工资系统 | 延后 | 实际首要需求是数据标注计件劳务结算 |

## 4. FinLedger Pro 的差异

FinLedger Pro 不是缩小版 Xero：

- 本地优先、可完全离线，而不是云端优先；
- 面向单一经营者，而不是会计师事务所多人平台；
- 新加坡、中国、SGD 和 CNY 是核心概念；
- 数据标注项目成本和计件结算是第一优先级；
- 通过中英文教学帮助经营者理解每一步背后的会计知识；
- 所有功能使用 MIT 许可证公开，没有订阅或收费版。
- 公司可以建立私有下游仓库，单向依赖公开核心的正式版本。

项目与 Xero 没有隶属、合作或授权关系，不使用 Xero 源代码、商标、截图或专有资源。“借鉴”仅指学习公开文档所展示的通用会计工作流和内部控制方法。

## 5. 第一个生产工作流

```text
合格标注成果
→ 承包者计件结算
→ 应付账款与项目成本
→ 导入银行付款
→ 银行对账
→ 试算平衡
→ 利润和现金报表
→ 期间锁定
```

第二条闭环是：

```text
客户合同 / 项目
→ 发票
→ 应收账款
→ 导入收款
→ 银行对账
→ 项目收入和毛利
```

完整闭环比许多互不连接的页面更有生产力，因为它证明业务数据无需电子表格即可到达总账、银行和报表。

## 6. 生产力要求

| 能力 | 行为 |
|---|---|
| 行动中心 | 集中显示待对账流水、逾期发票、到期账单、待结算和备份健康状态 |
| 快速录入 | 键盘优先、模板、最近值、附件和尽量少的默认字段 |
| 单据收件箱 | 统一接收账单、收据、银行文件和产量记录 |
| 周期规则 | 自动生成草稿，不静默过账 |
| 银行规则 | 基于已确认历史建议科目、联系人、税务和项目，并显示可信度 |
| 批量复核 | 低风险相似记录可批量批准，但过账前必须预览 |
| 搜索与下钻 | 每个报表数字都能追溯到源单据、分录和附件 |
| 结账助手 | 引导银行对账、计提、折旧、复核、报表、备份和期间锁定 |

## 7. 可靠性要求

- 不允许不平衡分录进入账本；
- 单据和全部分录行要么一起成功，要么一起回滚；
- 重试同一操作不能产生重复财务影响；
- 已过账历史只能通过关联冲销或贷项更正；
- 关闭期间拒绝普通修改；
- 银行文件和流水必须查重；
- 每次银行匹配保存原始流水、账簿记录、时间和决定；
- 税率、汇率、社保和计件规则都保存生效日期及版本；
- 迁移、批量导入和高风险更正前自动备份；
- 定期自动恢复验证备份可用；
- AI 或汇率接口失效时，核心记账继续工作。

Xero 使用云端加密、冗余、访问控制和安全审计保护数据。单机本地软件无法复制云端冗余，因此 FinLedger Pro 通过静态加密、系统密钥链、自动锁定、本地轮换备份以及用户控制的异地副本实现同一目标。

参考：[Xero 数据保护](https://www.xero.com/security/data-protection/)和[Xero 安全](https://www.xero.com/us/security/)。

## 8. 如何学习 Xero 而不复制

如果可以使用演示或试用组织，只录入虚构数据：

1. 建立虚构公司和科目表；
2. 添加客户、供应商和承包者；
3. 创建发票、账单以及部分/全部付款；
4. 导入或查看银行流水并对账；
5. 把收入和成本分配到项目并检查毛利；
6. 查看试算平衡、三大报表和应收应付账龄；
7. 锁定期间并检查审计历史；
8. 记录每一步的用户目标、必需数据、状态变化、分录、错误恢复和证据。

研究问题始终是：“哪个不变量和工作流让这一步值得信任？”而不是“怎样复制这个页面”。

---

## 9. 成功标准

- 普通账单、发票和承包者结算无需手工分录；
- 所有看板数字都能下钻到证据；
- 用户可以识别每条待对账流水和每笔逾期应收应付；
- 已关闭月份可以从源单据和审计历史复现；
- 重试、崩溃或重复导入不能重复记钱；
- 备份可以在另一套干净安装中恢复完整账簿；
- 关闭 AI 不影响任何记账功能；
- 会计师可以直接检查科目表、试算平衡、日记账、报表和审计轨迹。
