# 开放 API 与多币种策略

[English](open-api-and-multi-currency.md) | [简体中文](open-api-and-multi-currency.zh-CN.md)

> **状态：** 架构与产品策略
>
> **首批验收货币：** SGD 与 CNY
>
> **目标：** 在不依赖网络或单一供应商的前提下，支持更多货币和开放数据服务。

---

## 1. 概念区别

**开放 API（open API）**是公开文档和调用规则的接口；**开源 API 实现（open-source API implementation）**还会公开服务端代码，并通常允许自行部署。二者不是同一个概念。

FinLedger Pro 按以下顺序选择服务：

1. 条款清晰的权威公开数据；
2. 开源且可自行部署的服务；
3. 文档完整、可通过适配器替换的公开 API；
4. 必须始终存在的手工录入和文件导入方案。

任何可选 API 都不能成为打开账簿、录入、过账、对账、结账、报表、导出、备份或恢复的前置条件。

---

## 2. 首批候选供应商

### Frankfurter

[Frankfurter](https://frankfurter.dev/) 是无需密钥、可自行部署的开源汇率 API，聚合机构数据源并提供当前、历史和时间序列接口。它同时有公共服务和自托管路径，因此是首选适配器候选。

### 欧洲中央银行

[ECB Data API](https://data.ecb.europa.eu/help/getting-data-web-services-sdmx-0) 提供欧洲央行统计数据的官方接口。ECB 参考汇率包含 SGD 和 CNY，但 ECB 明确说明这些汇率用于信息参考，并不建议直接作为交易汇率。因此系统只把它作为可追溯的参考来源，不自动视为会计或税务权威汇率。

### 手工汇率

手工供应商始终启用。用户可以录入银行、合同、法定或会计师确认的汇率，并附上来源。手工录入不等于不可追溯：必须保存来源说明、生效日期、操作人和原因。

在许可证/条款、可用性、历史覆盖、SGD/CNY 行为、日期语义、精度和故障模式完成测试前，不永久绑定任何供应商。

---

## 3. 供应商边界

领域模型不识别任何供应商专属响应格式。每个适配器必须转换为统一结构：

```text
ExchangeRateQuote
  base_currency          # ISO 4217 基准货币
  quote_currency         # ISO 4217 报价货币
  rate                   # Decimal；方向必须明确
  rate_date              # 汇率经济生效日
  retrieved_at           # 本地获取时间
  provider_id
  source_url
  rate_type              # reference | market | bank | statutory | manual
  is_stale
  raw_payload_hash       # 不保存秘密信息的证据摘要
```

统一报价约定为：

```text
1 单位 base_currency = rate 单位 quote_currency
```

供应商数据需要反转或交叉换算时，必须显式处理并测试；业务逻辑不得隐式猜测汇率方向。

---

## 4. 多币种数据模型

数据库从第一天起支持 ISO 4217 货币代码，生产验收首先覆盖 SGD 与 CNY，随后验证 USD 和 EUR。

每笔业务交易永久保存：

```text
transaction_currency     # 原币
transaction_amount       # 原币金额
functional_currency      # 本位币
functional_amount        # 本位币金额
exchange_rate
rate_date
provider_id
rate_type
is_manual_override
rounding_policy_version
```

每套企业账簿只有一个**本位币（functional currency）**。报表可以选择额外的**列报币种（presentation currency）**，但切换列报币种不能改写总账。

历史交易必须永久保留当时汇率快照。刷新今天的汇率不能改变以前的发票、结算、付款或报表。

---

## 5. 会计处理

系统必须区分：

- **交易日折算：** 源单据同时记录原币金额和本位币金额。
- **实际结算：** 比较收付款的本位币金额和账面金额，确认已实现汇兑损益。
- **期末重估：** 按配置规则重估符合条件的货币性项目，确认未实现汇兑损益。
- **合并折算：** 为列报目的折算其他主体的报表，并把折算差额与经营利润分开。

所有规则都必须带生效日期和版本。税务或法定汇率可能不同于参考汇率和银行成交汇率，应单独配置。

---

## 6. 离线、缓存与故障策略

1. 成功获取的汇率连同供应商、日期和证据元数据保存在本地。
2. 周末或节假日只能使用最近一个可用工作日的汇率，并显示真实汇率日期。
3. 选择汇率时始终展示来源和数据年龄。
4. 格式错误、零值、负数、非 `Decimal` 或异常跳变的数据进入人工检查。
5. 使用有上限的超时和退避重试，不允许接口无限阻塞记账。
6. 按“备用供应商 → 本地缓存 → 手工录入”顺序降级。
7. 不得静默替换已确认或已过账的汇率。
8. 如果响应可能包含敏感信息，不得把完整载荷写入日志。

---

## 7. 只读外部集成

同一适配器模式可以支持只读银行账户、余额和流水，税务参考资料更新、发票投递状态、企业/联系人参考数据以及会计师或法定格式导出。

每个集成都必须说明认证方式、数据分类、权限、调用限制、超时与重试、幂等、审计事件、离线行为和退出方案。不能因为某个 API 可以调用，就默认把财务数据发送到外部。

银行能力是从银行进入 FinLedger Pro 的单向证据通道。供应商契约不包含创建转账、付款审批、收款人管理、批量付款、自动扣款、退款、在线收款或银行卡操作。流水必须先进入暂存区，不能直接过账。公司专属适配器可以按[公开核心与公司私有仓库](public-core-and-private-company-repos.zh-CN.md)的规则保存在下游私有仓库。

---

## 8. 验收测试

- SGD↔CNY 直接或交叉汇率在规定精度内复现已知测试样本。
- 汇率求逆并换算回来时，差异不超过明确的舍入容差。
- 缓存刷新或供应商切换不能改变已过账交易。
- 离线状态下仍可录入、过账、对账、结账、出报表、导出、备份和恢复。
- 重复响应不能产生重复汇率记录。
- 重复读取同一银行分页或交易不能产生重复流水或重复分录效果。
- 契约测试证明银行供应商没有任何资金移动方法。
- 供应商故障必须按降级顺序处理，并显示过期或手工汇率提示。
- 已实现和未实现汇兑损益案例能够与总账核对一致。
- 每一个换算金额都能追溯到汇率、来源、日期和舍入规则。

---

## 9. 重新评估条件

当公司增加新的本位币、需要特定司法辖区的法定汇率或需要日内汇率时，重新评估多币种设计。当流水数量、分页或持续同步要求常驻任务时，重新评估由公司运行的只读同步服务。该评估不扩展到付款功能；资金移动始终在 FinLedger Pro 边界之外。
